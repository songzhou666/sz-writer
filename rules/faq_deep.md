# 深度 FAQ（边缘场景 / 工具兼容 / 安全合规）

> 用途：主文档 `SKILL.md §11` 覆盖高频通用问题；本文件补充**边缘场景**，供 Agent 在异常与长尾情形下保持一致口径。
> 引用：`SKILL.md §2.4 会话机制`、`§8 异常与边界`、`§9 付费调用流程`。

---

## 一、会话与续写

### Q1：用户新开会话，状态卡丢了，怎么接着写？

先**不要重走全流程**。按以下顺序恢复：
1. 请用户提供上一版**成稿文本**或**会话状态卡**（状态卡在哪里都能复制）。
2. 有成稿 → 直接从「改写/修订模式」进入，用成稿反推文种与画像，一句话向用户确认"我按 XX 文种继续，对吗"。
3. 都没有 → 说明跨会话无自动恢复，请用户用一句话重述需求（方向 + 场景 + 用途），从 S2 画像重新开始。
4. **禁止**凭猜测假定文种后直接起草。

### Q2：用户同时要写两篇不同文种，会重复收费吗？

不会。同一支付凭证 **120 分钟窗口内**不限文种与篇数。正确做法：
- 两篇共用**同一个支付凭证**，各自独立走选型 → 起草 → 审核。
- 两篇的**状态卡分别维护**，不要混在一张卡里，避免画像串味。
- 若两篇间隔超过 120 分钟窗口，第二篇按 §9 重新触发支付（此时应提前告知用户）。

### Q3：用户说"先别问那么多，随便写一版看看"？

走**低置信度降级**，但必须显式声明：
- 采用可安全推断的默认值（如方向=上行、用途=上报），并在回复开头写明"以下按【假设】XX 起草"。
- 把假设项集中列成"待你确认清单"（≤4 项），用户可一次性回改。
- **禁止**以"随便写"为由跳过选型与审核这两道门控。

## 二、工具与环境兼容

### Q4：平台没有命令执行（终端）能力，还能用吗？

分层次处理，**不要假装能用**：
| 能力 | 缺失后的降级 |
| --- | --- |
| 命令执行 / 支付工具 | 无法加载 L1/L2 资产 → 明确告知"当前环境暂不支持获取精细化资产"，询问是否改用**通用骨架兜底起草**（并明示局限） |
| 临时文件写入 | 降级为**内联状态卡**随回复携带；支付凭证流程按 §9.1 的最小可用方式处理 |
| 联网检索 | 未收录文种无法提炼临时资产 → 只能走通用骨架兜底，并明示"该文种精细化资产建设中" |
| 以上全部缺失 | 仅保留：选型咨询、易混文种判定、国标格式指导、来稿评估与去 AI 味——这些不依赖资产与联网 |

### Q5：`alipay-bot` 装不上 / 授权失败怎么办？

1. 先确认是否真的缺失：`alipay-bot` 是**命令行工具**，**不出现在工具列表里**——只按"工具列表有没有支付工具"判断会误判。
2. 安装失败 → 输出可复制的安装命令与失败原因，让用户手动执行后重试，**最多重试 1 次**。
3. 授权失败 → 提示"支付授权未完成，请重新扫码授权（授权免费，不扣钱）"，不重复拉起。
4. 反复失败 → 停止重试，告知"当前环境暂不支持获取精细化资产"，提供通用骨架兜底选项。

### Q6：在纯对话环境（无文件写入）里，HTML 公文怎么交付？

- 降级为**代码块**呈现完整 HTML；在代码块前用一句话说明"复制保存为 `.html` 即可查看排好版的公文"。
- **不要**声称"已生成文件"或"文件已保存到 XX 路径"——这是能力越界。
- 若平台支持文件交付能力（如 `present_files`），优先走文件交付。

## 三、支付与交付异常

### Q7：用户已扫码支付，但资产没返回（207 / `RESOURCE_DELIVERY_FAILED`）？

用**同一 `trade_no`** 重新执行查询，最多 2 次：
- **不要**加 `--recovery-action`（CLI 0.4.2 无此 flag，会报 `unknown flag`）。
- **不要**重新出码、**不要**让用户重新付款。
- 仍失败 → 输出四件事：① 资产服务暂不可用；② 交易号 `trade_no`；③ "若已支付未交付，请凭交易号联系制作方对账、补发或退款"；④ 询问是否改用通用骨架起草。

### Q8：如何判断"到底成功了没有"？

**禁止用进程退出码判断**——交付成功时 exit code 也可能是 `1`。唯一判据：
> `resourceResponse.body.content` **非空** = 成功。

特别注意**假失败**：CLI 返回 `success:false` + `FULFILLMENT_FAILED`，但 `resourceResponse.status==200` 且 `content` 非空 → **视为成功，直接起草**，不得让用户重新支付。

### Q9：凭证过期（400 `INVALID_PAYMENT_PROOF`）要重新收费吗？

只有**超过 120 分钟窗口**才需要。处理：
- 400 且原因为**过期** → 提示"凭证已超过 120 分钟有效期"，**不带凭证**重新调用触发新支付。
- 400 且原因为**凭证无效** → 重新走 402 → 支付流程；**明确告知用户"不要让用户重复付款"**，先检查是否已有成功交易。
- 查询到 `TRADE_ALREADY_PAID` → **直接用原 `trade_no` 查资源**，绝不重新支付。

### Q10：等待用户扫码时该等多久？重试几次？

两套机制**严禁混用**：
| 场景 | 策略 |
| --- | --- |
| 等待轮询（用户尚未扫码） | `payment_unconfirmed` 属**预期状态，不计重试次数**；每 **10–15 秒**查一次，**最多 30 次**（约 5 分钟）；`content` 非空即停 |
| 失败重试（报错/超时/5xx） | 支付相关操作**最多重试 1 次**；网络超时重试前至少等 2 秒 |

连续失败 3 次（含 207、400/500/503 重试耗尽）→ **立即停止**，按 Q7 的四件事输出，禁止原地空转。

## 四、安全与合规

### Q11：什么算"涉密/敏感"，边界怎么判？

**命中即拦截，不进任何后续阶段**，典型包括：
- 标注密级（绝密/机密/秘密）或明确要求定密的材料；
- 未公开的案件侦办、人事酝酿、执法查处细节；
- 未脱敏的个人身份信息（身份证号、银行账号、完整住址、健康状况等）；
- 涉及国家安全的设施、系统、数据与人员信息。

边界不清时 → **先问一句**"这份材料是否需要定密/含未公开敏感信息？"，由用户确认后再继续；**宁可多问一句，不可擅自处理**。

### Q12：用户粘贴的真实人名、单位、金额会不会被上传？

不会。资产服务**只下发骨架与句池，不接收用户文稿**，文稿只存在于当前对话上下文。建议做法：
- 起草阶段先用「XX 单位 / X 万元 / 张三」占位，定稿后再回填真实信息；
- 交付前提醒用户"发布前请按本单位保密要求自行复核"。

### Q13：用户坚持用一个明显错误的文种（如把请示写成报告）怎么办？

遵从**用户意愿最高优先级**，但必须留痕：
1. 用一句话给出**判别依据**（依据《党政机关公文处理工作条例》：请示需上级批复、报告不得夹带请示事项）。
2. 按用户指定文种起草，**不得擅自改写文种**。
3. 在交付物开头加**醒目风险提示**（如"⚠️ 本文按你指定的『报告』撰写；但该事项属请求批准，规范文种应为『请示』，请知悉"）。

### Q14：用户指定要"照着我给的范文写"，怎么处理？

这是**风格对齐**场景，不是照抄：
- 从范文提取：结构骨架、段落节奏、常用句式、称谓习惯、语气调性；
- **只迁移风格，不迁移事实**——范文里的单位、数字、政策依据一律不得带入新稿；
- 若范文文体与目标文种不一致（拿工作总结的调子写请示），先提示风险再决定是否仍需对齐。

## 五、质量与审核

### Q15：审核打回后，只改措辞算不算修好了？

**不算，属"假修复"，禁止交付。** 判定标准：
- 阻断项（`BLOCK-*`）必须**回到对应阶段重做**（文体错 → 回 S4；事实缺失 → 回素材补全；格式不合国标 → 按国标参数重排）。
- 修复后必须**重新过一遍完整六维审核**，不能只看被点出的那一项。
- 同一阻断项**连续 2 次未修好** → 停止循环，向用户说明卡在哪一项、需要补充什么。

### Q16：评估模式（打分）和写作模式同时触发怎么办？

**以用户文稿优先**（既有文稿，则以 C/B 类优先）：
1. 先出**评估报告**（六维打分 + 原文证据 + 改进建议）；
2. 报告末尾询问"是否需要我按建议直接改出一版"；
3. 用户同意 → 进入改写流程；**不得**未经确认直接覆盖用户原文。
