# 应用文评估报告（模板）

> 能力定位：任务类型 C / 用户已有文稿的「分析与评估」。与自产稿六维审核不同，评估对**用户的原稿**做
> 多维度诊断打分，输出《应用文评估报告》，逐项引用原文证据，给出改进建议与可一键发起改进的链接。
> 综合评估总分满分 100，用于横向直观对比。产物中文命名：`评估报告.md`（会话内文本呈现）。

```markdown
# 应用文评估报告

- 被评估文种（用户主张）：________
- 判定结果：文体匹配 ✅ / 疑似错配 ⚠️（附推荐文种）
- 评估依据：资产正文《____/____.md》＋用户原稿
- 评估时间：YYYY-MM-DD

## 一、总体结论
- 综合得分：____ / 100　（档位：优 ≥85｜良 70-84｜中 60-69｜待改 <60）
- 一句话点评：____
- 功能是否达成用户写作目的：✅ / ⚠️ / ❌

## 二、分维度评估（逐维打分 + 证据引用）

| 维度 | 得分(/分) | 等级 | 证据与诊断（引用原句→问题→影响） |
| --- | --- | --- | --- |
| ① 文体匹配 | 15 | 优/良/中/待改 | （例："请示性内容却以'报告'结尾'特此通知'"→ 文种误用 → 正式上报有被退回风险） |
| ② 结构完整 | 20 |  | （例：缺结语'妥否，请批示'→ 请求未被收文方识别为核心要素） |
| ③ 语言规范 | 20 |  | （例：句"……无可厚非"与公文语体不符） |
| ④ 语气对象感 | 15 |  | （例：对上行文用"请予知悉"指令腔 → 失去谦恭） |
| ⑤ 事实支撑 | 15 |  | （例：主体段连续 2 段无数字/单位/具体对象 → 空转） |
| ⑥ 去AI味 | 15 |  | （例：'赋能''闭环'硬禁词命中 R1；'此外'连用 3 次 R3） |
| ⑦ 事实核对（复核） | —（不计分） | 命中/0命中 | （例：用户给定 3 个数字/2 个日期逐项在稿中检索，命中 5/5；出现 0 命中即判 BLOCK-事实） |
| ⑧ 交付规格（复核） | —（不计分） | 达标/未达标 | （例：用户要求 ≥800 字，实测正文中文字符 812（不含标题落款）；格式要素齐备；删法定要素已作合规差异提示） |
| 合计 | 100 |  |  |

> 每个扣分项必须带原句引用；无依据的"整体不错"结论一律禁止。
> ⑦⑧ 为新增复核栏，**不计入 100 分加权**，只出"命中/达标"结论（判定口径见 `rules/audit_rules.md`）。

## 三、醒目标识
- 🔴 硬性问题（必须改）：文体错配、涉密残留、事实编造、（评估语境下）杜绝发布风险。
- 🟡 优化建议（建议改）：结构缺失、语气错位、空转段、AI 指纹词密度。
- 🟢 亮点（值得保留）：____

## 四、改进建议清单（可一键发起改进）
| # | 位置 | 问题 | 建议改法 |
| --- | --- | --- | --- |
| 1 | 第 X 段"____" | ____ | ____ |
> 末尾提供操作入口："需要我按以上建议优化吗？／按正确文种重写？／仅做润色？"三选一（对齐 S5 用户意愿优先）。

## 五、文体诊断（若命中"疑似错配"时单独呈现，走 S5 三选一）
- 错误原因：____
- 标准文种推荐：____（行文方向不正确→改用____）
- ⚠️ 公文合规风险提示：根据《党政机关公文处理工作条例》，当前业务场景不适用本文体，正式上报、发文存在被退回、不合规风险，请谨慎使用。

## 六、涉密与合规复核
- 涉密残留：✅ 无 / ❌ 命中（阻断处理）
- 用户素材事实一致性：✅ / 差异清单

## 七、素材不足降级
> 当用户提供的文稿/背景不足以支撑六维客观打分（如仅片段、缺主体事实）时，不强行打分：
> 输出"素材不足，以下为参考性诊断 + 待补充信息清单"，仅给文体/语气等可判维度参考结论，标注"非定论"，
> 并引导用户补充后再出正式评估报告（对齐 SKILL §6 片段输入→降置信度）。
